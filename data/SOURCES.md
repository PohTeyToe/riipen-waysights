- **Collected (real, fetched on the run date):** every page, PDF and dataset row listed below. `run/pages/{slug}.json` holds the exact text each quote was checked against, for every page the run took a value from or refused one from (for PDFs, only the pages read; whole third-party PDFs are not committed). Pages the run read but took nothing from keep only their sha256 here; there's no reason to copy them. The saved pages are public municipal pages, and some list staff names and work email addresses. `pipeline/tests/fixtures/` keeps saved copies of four pages and two PDF pages for the tests (origins and sha256 in `fixtures/SOURCES.json`).

- **Written by hand before the first run:** `answer_key.json`, by reading the sources directly (commit `f7023e6a7759`).

## How the run was made

The answer key was committed before the pipeline ran at all. The pipeline was then built and run several times on these same six Accounts (some runs from a local fetch cache), so the scorecard checks it on pages it was developed against. It is a check, not a benchmark. The outputs in `run/` are from one final live run with no cache, at the pipeline commit in `run/meta.json`.

Tompkins County's site refused scripted requests (HTTP 403, robots.txt included) when the demo brief was written earlier on 2026-10-15. It answered 200 to every request in these runs, so it is scored as an ordinary Account.

Changes made after development runs, each a general fix rather than a per-site rule:

- Discovery read the sitemap too early and spent the budget on project pages; it now reads the sitemap only when the site's menu runs out, skips project and construction pages, and treats URLs that differ only in their query string as one page.
- Text after a `<br />` was dropped on one page (Saratoga County's contact block); it is now kept, with a test.
- lincoln.ca sends an incomplete certificate chain; TLS is now verified by the operating system's trust store, which completes the chain and still rejects bad certificates.
- PDF page picking missed table rows whose unit is in the label ("kms of local roads 255"); fixed, with a test.
- One development run judged Lincoln's 255 + 55 km as part of the network because arterial roads show as 0; the extraction prompt now says a type given as zero, or roads another government owns, doesn't break coverage.
- The brief writer is now told which numbers it may use, and not to attach a department's phone to a person.
- The New York dataset query got its own small request budget after long crawls used all 15 requests.
- In one development run the model gave Tompkins County's unit as "highway miles", and the unit check refused it, so the county's own figure dropped out and the run filled the state number without asking. The answer key caught it. The check now reads the last word of a unit, and refuses lane miles the way it refuses lane-km.
- Contacts now carry only a name and title: the phone and email the sites print belong to the department, so they go on the Account.
- Scoring compares URLs ignoring `https://`, `www.` and a trailing slash (decided after a development run listed www.warrencountyny.gov/dpw for the key's warrencountyny.gov/dpw).

After review of an earlier final run (pipeline commit 21ee5db; it scored 24 right, 1 wrong, 7 correctly blank, 0 missed, 4 sent to a person), these changes were made and the run was repeated from scratch. The wrong one was Pelham's phone: the run filled 905-892-2607 x332 from one page while the contacts directory prints ext. 33.

- Phones: the extractor now lists every number a page prints for the department, and two different numbers go to a person instead of one being picked.
- An approximate figure now agrees with a precise one that rounds to it at the precision it is printed with, so Lincoln's "approximately 300km" no longer competes with the plan's 310 km. Real disagreements still ask.
- A road length's unit must be printed next to its number, a money amount is never a length, a total can't count one line twice, and a quote can't cite a PDF page the run didn't read.
- The Account brief is now one or two sentences: what the municipality says about its signs, and who to ask for. It no longer repeats the road length or quotes the sign rules, and each sentence must share a checked value or four words in a row with every page it cites.
- The Account is updated by its record id instead of matched by name, and the department's phone goes to its own field instead of the Account's main Phone.
- Duplicate check: two different full first names never match.
- Fetching: a redirected robots.txt is read where it lands, `..` in a path is refused, a broken PDF is skipped, and a run that reads nothing is marked Failed instead of Done.
- Discovery spent Warren's and Tompkins' budgets on other departments' contact pages (Sheriff, Social Services, Board of Elections) and West Lincoln's on every page under "Plans, Studies and Reports". A bare "Contact" link now counts only as the site's own contact page, and the plans-and-reports words count on a link's text, not on every path under that section.

The first repeat asked the extractor for every number printed for the department, and it listed staff extensions, after-hours lines and another program's office, so four Accounts got a phone conflict that wasn't real. The extractor now returns only the number a page gives for the department itself, and sign lines must be about signs in general. A second repeat had the brief call Tompkins County's Highway Department "Public Works"; the brief now names the department the way its page does. The discovery change above came after the third repeat, so the outputs from that round came from a fourth.

After review of that run (pipeline commit 731e55e; 24 right, 0 wrong, 7 correctly blank, 0 missed, 5 sent to a person), these changes were made and the run was repeated from scratch:

- Rule 4: two road lengths within 2% of each other are the same roads measured twice. The precise figure is kept, the Account's own page before the state's data, and the other is shown beside it. Warren (398.1 km on the county's page, 393.2 km in the 2020 state data) and Tompkins ("close to 302 highway miles" against 300.62 mi) no longer ask a person to pick between figures about 1% apart. The answer key, written before the first run, sends both to a person, and its rules count filling them as wrong. The key is unchanged.
- Checks: emails and phones must be printed whole (a review found "x33" passing against "x332"), the 2 of "m2" or "km²" is not read as a number, a total uses each printed number once however its lines quote it, a county with no dataset rows gets no state figure instead of 0 km, and every word of a brief sentence must be printed on a page it cites, apart from a short list of connecting words.
- Write-back: a Contact merge sends only the fields the run found, so a missing title is never sent as null.
- Fetching: robots.txt refusals and off-list redirects are recorded as fetch errors, so a failed run's Note says why.
- Discovery: a link counts on its own words and its page's own name, not the folder it sits in (Warren's Public Works folder also holds its composting and solid waste pages). Other departments' pages are skipped even when they say "road" (Saratoga's DMV road tests, Tompkins' Sheriff road patrol), a link whose text is its URL has no words, a bare "Contact Us" counts only near the site's root, sign pages are wanted, and plan PDFs compete on their year alone, so the newest is read.
- Sign lines: a list that only names signs among other assets (Lincoln's "parking lots, signs, playground equipment") is not sign work.
- No Account brief when the pages say nothing about signs, since it would only repeat the contact fields (Saratoga). Waysights' own pages are no longer read: they were there for the brief's vocabulary, and no kept sentence ever cited one.

In the first repeat the stricter brief check dropped good sign sentences: the prompt still asked for Waysights' words, and the check split "County's" into two words. The prompt now lists the connecting words the check allows and the check reads a possessive as its word, so the outputs here are from a second repeat.
